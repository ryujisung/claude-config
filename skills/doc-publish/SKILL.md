# doc-publish — Confluence 문서 작성·갱신 (정본 = Confluence)

팀 지식 문서의 **정본은 Confluence `TSSNN`**(이 위키)다. 사람은 Confluence 에디터에서 직접 쓰고, AI는 이 스킬로 안전하게 만들거나 고친다. 코드는 GitHub, 할 일은 Jira(=`/jira-write`).

> **발동 범위**: 대상이 **Confluence(TSSNN)**일 때만. soma 경영문서(`founder/`·`ops/`)·explainers 설명·Jira 카드·단순 대화면 발동 안 함. 애매하면 "Confluence에 쓰는 거 맞아?" 1줄 확인.

## 불변식 (어기면 작성 중단)
1. ⚠ **갱신 전 통째로 읽기.** 기존 페이지를 고칠 땐 **반드시 `getConfluencePage`로 본문 전체를 먼저 읽고**, 그 위에서 수정한다. **절대 빈/placeholder/잘린 본문으로 덮어쓰지 않는다**(본문 파손 사고의 원인 — 2026-06-22 실제 발생). read 실패(타임아웃·50KB 초과·deferred 미로드)면 **중단**.
2. **쉬운 말로.** 영어 약어·내부용어 빼고 일상어로. 꼭 필요한 도구명만 괄호로 1회 풀기(예: "GitHub(코드 저장소)"). **PM이 제일 많이 읽는다.** (예외: 배우용 coach 결과물은 연기 현장어 — 읽는 사람이 다름.)
3. **머리 3줄 의무**: `상태:` → `【한 줄 요약】` → `【결론】`(1~3개). 그 아래 본문.
4. **폴더 이동(parentId 변경)은 사람이 UI에서.** 스킬은 페이지를 옮기지 않는다(이동은 본문 재저장을 강제해 위험).

## 절차
### 1. 입력 확정
- 무엇을 · **어느 6분류 폴더**(아래 §배치) · **새 페이지 / 기존 갱신** · 연결 티켓(SOMA-NN, 있으면).
- 불명확하면 추측 말고 1개만 되묻는다(특히 폴더·새/갱신·기존이면 pageId).

### 2. 본문 작성
- **머리 3줄**(불변식 3) + **종류별 형식 = Confluence "운영규칙" page `12681218` 표**(기획/PRD·UC·리서치·결정·회의록·회고·검증/피드백·시스템·디자인·멘토자문).
- **쉬운 말**(불변식 2). 결론 먼저·짧게.
- **보기 좋게**: 두고두고 읽는 문서(기획·결정·규칙·검증)는 `contentFormat:"html"`로 **패널·상태 뱃지**를 써서 구획을 만든다 — 머리 3줄은 `<div data-type="panel-info">`, 상태는 `<span data-type="status" data-color="green">확정</span>`, 강조 박스는 `panel-note/warning/success`. 로그성(회의록·데일리)은 `contentFormat:"markdown"`로 가볍게. (※ md만 올리면 패널·뱃지가 평문이 돼 읽기 나빠짐 — 중요 문서는 html.)
- **연락처·재무 등 민감정보(restricted)는 본문에 직접 넣지 않는다** — 요약·링크만, 원본은 접근 통제(§8).

### 3. 발행
- Atlassian Rovo MCP는 deferred → `ToolSearch`로 `getConfluencePage,createConfluencePage,updateConfluencePage` 로드.
- 고정값: cloudId `205faf1b-4810-4ed3-843d-410a3a6dcc9b`, spaceId `688140`(TSSNN).
- **새 문서**: `createConfluencePage(spaceId, parentId=해당 6분류 폴더, title, body, contentFormat)`.
- **기존 갱신**: 먼저 `getConfluencePage(pageId)`로 **본문 전체 읽기(불변식 1)** → 그 위에서 고쳐 `updateConfluencePage(pageId, title, body, contentFormat, versionMessage=<요약>)`. 버전은 자동 증가.
- markdown 포맷은 표·패널이 단순화될 수 있다 → 패널이 필요한 중요 문서는 html.

### 4. read-back 검증·보고
- 발행 직후 `getConfluencePage(pageId)`로 **머리 3줄·핵심 섹션이 살아있는지** 확인(빈 본문·잘림 없는지).
- 보고: pageId · Confluence url · 한 줄 요약. 검증 못 한 항목은 "검증 안 됨:"으로.

## 거부 조건 (걸리면 중단·사유 보고)
- 갱신 시 본문 전체 안 읽고 덮어쓰기(불변식 1) · 빈/placeholder body · 머리 3줄 누락 · 어려운 영어 약어 본문 노출(쉬운 말 위반) · parentId 이동 시도 · restricted 본문 직접 게재 · MCP read 실패.

## 실패 폴백
- 발행 실패하면 본문을 신 포맷 md로 사용자에게 전달하고 사람이 수동 발행. 페이지 본문이 깨지면 **Confluence UI 페이지 기록에서 직전 버전 복원**.
